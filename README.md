# GCLI - gcode (editor) cli

I'm working with gcode files on a daily basis. It happens frequently that I forget to add an instruction or I want to add a "wait" before the next layer starts...

This is the goal of GCLI, allowing quick gcode edits in seconds!

## Why Zig?

This is a perfect use-case for Zig. It allows faster file processing without RAM or CPU overhead. Zero external dependencies and a lot of OSes and Architectures supported.

## How to use it

### 1a: build it

It's easy:
1. be sure to have [Zig 0.16](https://ziglang.org/download/) in your system (you could check it using `zig version`)
2. `cd gcli`
3. `zig build` (selection of different os and arch than `linux-x86_64` soon!)

### 2: use it

Basic usage `gcli <ACTION> <GCODE FILE> [OPTIONS]`.

Action means a choice between those two functionalities:
- `get-metadata`: it prints useful file information (all the flags here will be ignored),
- `edit`: set gcli in edit mode, here the flags will be executed.

Each flag that targets a line/layer must be followed by a `--instruction` flag.

**FLAGS**
- `-h`, `--help` - Display this help and exit.
- `-l <INT>`, `--line <INT>` - Insert the instruction at the specified line number, pushing the original line down.
- `--before-line <INT>` - Same as --line, but targets the preceding line (N-1).
- `--after-line <INT>` - Same as --line, but targets the following line (N+1).
- `--layer <INT>` - Select the start of layer X (requires slicer layer markers).
- `--end-layer <INT>` - Select the end of layer X (requires slicer layer markers).
- `--each-layer-start` - Insert something before each layer's start.
- `--each-layer-end` - Insert something after each layer's end.
- `--at-gcode-start` - Insert something at the start of gcode.
- `--at-gcode-end` - Insert something at the end of gcode.
- `--gcode-template <FILE>` -  Use a Gcode template.
- `--after-instr <STR>` - Insert something after another instruction.
- `--before-instr <STR>` - Insert something before another instruction.
- `-i <STR>`, `--instruction <STR>` - Instruction to be inserted.
- `-o <FILE>`, `--output <FILE>` - Path of output file. Default is the original path but with `-gcli` before `.gcode`.

> For example: `--line 1 --instruction "G1 ..." --line 3 --instruction "G2 ..."` will be rendered as `G1 ...\nG2 ...`. Using another line flag will overwrite the previous instrunction `--line 1 --instruction "G1 ..." --line 2 --line 3 --instruction "G2 ..."` the result would be `G1 ...\n\nG2 ...`.

> Using two `--instruction` next to each other will result in a concatenation of gcode instructions.

> Note on layer-based flags: Layer detection relies on standard layer comments generated by your slicer (e.g., PrusaSlicer, Cura, OrcaSlicer). If the target G-code lacks recognizable layer markers, layer flags and variables will have no effect. You can run the get-metadata action first to verify if layer detection is supported for your specific G-code file.

**Quick examples**
- Change filament after layer 50: `gcli edit print.gcode --end-layer 50 --instruction "M600 ; change color!"`
- Showing a custom message each time a layer starts: `gcli edit print.gcode --each-layer-start --instruction "M117 Starting layer %LAYER-NUM"`
- Play a [short tune](https://marlinfw.org/docs/gcode/M300.html) when the print ends: `gcli edit print.gcode --output tune.gcode --at-gcode-end -i "M300 S440 P200" -i "M300 S660 P250" -i "M300 S880 P300"`

**Placeholders**
- `%LAYER-NUM`: means the actual layer number (requires slicer layer markers),
- `%LINE-NUM`: means the actual line number (of the original file without edits)
Let's look at this example:
```gcode
G1 ... ; first line
G1 ... ; second line
; and so on...
```

It will be:
```gcode
; %LAYER-NUM=0
G1 ... ; %LINE-NUM=0
G1 ... ; %LINE-NUM=1
; and so on...
```

**Using a template**
Using a template is a declarative way to edit a gcode. Setting up a template is easy:

```gcode
;start
<INSTRUCTIONS>

;line A
<INSTRUCTIONS>
;line B
<INSTRUCTIONS>

;start-layer C
<INSTRUCTIONS>
;end-layer D
<INSTRUCTIONS>

;end
<INSTRUCTIONS>
```

> The use of `\n` has no effect and they will be ignored.

The template syntax is kept as simple as possible in a way that the "special comments" could be easily replaceable by command line flags.

The template will be parsed and applied in the target GCODE.
